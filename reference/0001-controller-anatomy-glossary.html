Controller Anatomy — Glossary

Core vocabulary for how a Custom Resource goes from stored data to running logic. Companion to Lesson 1.

CRD (CustomResourceDefinition)
A schema you register with the API server, teaching it a new kind of object (a new Kind/API path) it can validate and store — like adding a new built-in type such as Pod, but one you defined.
Avoid: "custom API" (too vague — CRD is specifically the schema registration)
CR (Custom Resource)
An actual object of a Kind that a CRD defines — the thing kubectl apply creates. On its own, a CR is just data sitting in etcd. Nothing executes because a CR exists; a controller has to be watching for it.
Manager
The top-level object in a controller-runtime program. It owns a shared Cache and Client, starts and stops one or more Controllers, and runs their reconcile loops.
Cache (Informer)
A local, in-memory mirror of objects from the API server, kept in sync via List + Watch. Reads inside a Reconciler go through this cache, not a live API call — that's what keeps controllers from hammering the API server.
Avoid: using "informer" and "cache" as if they're different things in this workspace — here, the informer is the mechanism that keeps the cache in sync.
WorkQueue
A queue of object keys (namespace/name), not events or object bodies. Multiple rapid changes to the same object collapse into one queued key — the queue tracks that something changed, not what changed.
Reconcile Request
The single piece of information a worker hands to your Reconcile function: a namespace/name. No payload, no diff, no event type.
Reconciler
Your code. A function shaped Reconcile(ctx, Request) (Result, error) that re-reads current state from the Cache and Client, compares it to what it should be, and takes action to close the gap.
Level-triggered
The design property where a Reconciler reacts to the current state of the world, not to the specific event that woke it up. It must be safe to call repeatedly, and safe to call even when nothing actually needs doing (idempotent).
Avoid: "event-driven" as a description of Reconcile itself — the workqueue is event-driven, but Reconcile is level-triggered. Keep the two separate.
Edge-triggered
The opposite property: reacting to a specific transition (this exact event, this exact diff). Naive event handlers are edge-triggered and fragile — miss one event and you're permanently wrong. Controllers deliberately avoid this.
Owner reference
A field (metadata.ownerReferences) on an object pointing back at the object that created it. Set via controllerutil.SetControllerReference. It does two unrelated jobs: it's what a secondary watch reads to redirect events, and separately it's what the cluster's garbage collector reads to cascade-delete children.
Secondary watch (Owns)
A watch on a Kind other than the one passed to For(), added via .Owns(&SomeKind{}) in SetupWithManager. It feeds the same WorkQueue as the primary watch, but translates each event into the owner's key (read from the owner reference) rather than the changed object's own key.
Avoid: assuming a secondary watch is a different mechanism from Lesson 1's WorkQueue — it's the identical queue, just fed by a second source with a translation step in front of it.
Garbage collection (cascading delete)
A separate control loop, built into Kubernetes itself (not your controller), that deletes an object once every owner reference pointing at it is gone. This is why deleting a Greeting removes its ConfigMap even though no line of your Reconcile code calls delete — your controller never runs for this at all.
Status subresource
A second API endpoint (/status) for an object, enabled by the +kubebuilder:subresource:status marker. Once enabled, a plain r.Update() silently ignores changes to .Status — you must call r.Status().Update() instead. The split exists so a user editing spec and a controller reporting status don't fight over the same write.
Condition
The standard shape for one fact in .status.conditions: a Type (e.g. "Ready"), a Status of True/False/Unknown, a machine-readable Reason, and a human Message. Set with meta.SetStatusCondition, which manages LastTransitionTime for you. This is the same convention almost every real-world CRD uses — recognizing it is what lets you read an unfamiliar operator's status output.
envtest
A controller-runtime library that boots a real etcd and kube-apiserver as local binaries for tests — full API validation and watches, but no kubelet, no scheduler, and critically no built-in controllers, so no garbage collection. Smaller than a k3d cluster on purpose: fast, hermetic, good for CI. Not a replacement for testing against k3d — a different, narrower layer.
