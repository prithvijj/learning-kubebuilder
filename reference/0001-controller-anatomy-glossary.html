Controller Anatomy — Glossary

Core vocabulary for how a Custom Resource goes from stored data to running logic. Companion to Lesson 1.

CRD (CustomResourceDefinition)
A schema you register with the API server, teaching it a new kind of object (a new Kind/API path) it can validate and store — like adding a new built-in type such as Pod, but one you defined.
Avoid: "custom API" (too vague — CRD is specifically the schema registration)
CR (Custom Resource)
An actual object of a Kind that a CRD defines — the thing kubectl apply creates. On its own, a CR is just data sitting in etcd. Nothing executes because a CR exists; a controller has to be watching for it.
Manager
The top-level object in a controller-runtime program. It owns a shared Cache and Client, starts and stops one or more Controllers, and runs their reconcile loops.
Cache (Informer)
A local, in-memory mirror of objects from the API server, kept in sync via List + Watch. Reads inside a Reconciler go through this cache, not a live API call — that's what keeps controllers from hammering the API server.
Avoid: using "informer" and "cache" as if they're different things in this workspace — here, the informer is the mechanism that keeps the cache in sync.
WorkQueue
A queue of object keys (namespace/name), not events or object bodies. Multiple rapid changes to the same object collapse into one queued key — the queue tracks that something changed, not what changed.
Reconcile Request
The single piece of information a worker hands to your Reconcile function: a namespace/name. No payload, no diff, no event type.
Reconciler
Your code. A function shaped Reconcile(ctx, Request) (Result, error) that re-reads current state from the Cache and Client, compares it to what it should be, and takes action to close the gap.
Level-triggered
The design property where a Reconciler reacts to the current state of the world, not to the specific event that woke it up. It must be safe to call repeatedly, and safe to call even when nothing actually needs doing (idempotent).
Avoid: "event-driven" as a description of Reconcile itself — the workqueue is event-driven, but Reconcile is level-triggered. Keep the two separate.
Edge-triggered
The opposite property: reacting to a specific transition (this exact event, this exact diff). Naive event handlers are edge-triggered and fragile — miss one event and you're permanently wrong. Controllers deliberately avoid this.
