Kubebuilder CLI & Makefile Targets

Quick lookup for the commands used in Lesson 2. Run from your project root unless noted.

kubebuilder init --domain <domain> --repo <module-path>
One-time, at the start of a new project. Scaffolds main.go, the Makefile, go.mod, and PROJECT config. --repo is your Go module path, not a real URL — it never needs to be published.
kubebuilder create api --group <g> --version <v> --kind <Kind> --resource --controller
Scaffolds a new CRD's Go types (api/<version>/<kind>_types.go) and a controller skeleton (internal/controller/<kind>_controller.go). Omit --resource/--controller and it will ask interactively instead.
make manifests
Regenerates CRD YAML (config/crd/bases) and RBAC YAML (config/rbac) from the Go struct tags and //+kubebuilder:rbac markers in your code. Run this after every change to a _types.go file or an RBAC marker.
make generate
Regenerates DeepCopy/DeepCopyInto methods your types need to satisfy runtime.Object. Run after changing a type's fields.
make install
Applies the generated CRDs to whatever cluster your current kubeconfig context points at. This is the step that teaches your k3d cluster's API server the new schema — see CRD in the Lesson 1 glossary.
make uninstall
Removes the CRDs from the cluster. Note: this deletes every CR of that Kind too — etcd has nowhere to store objects of a type the API server no longer recognizes.
make run
Builds and runs the manager as a local Go process on your machine, authenticating to the cluster via your kubeconfig. Fastest inner loop for development — no image build, no k3d image import. Ctrl-C to stop.
make docker-build docker-push IMG=<ref>
Builds the manager into a container image. With k3d, skip the registry push and instead run k3d image import <ref> -c <cluster> to load it straight into the cluster's containerd.
make deploy IMG=<ref>
Applies manifests that run the manager inside the cluster as a Deployment, instead of on your machine. Use once make run works and you want to test the real deployment path.
k3d cluster create <name>
Creates a new k3d cluster and merges its kubeconfig, switching your current context to it automatically.
k3d cluster list / k3d cluster delete <name>
List existing k3d clusters, or tear one down.
kubectl config current-context
Confirms which cluster make install / make run / kubectl are about to talk to. Check this before running anything destructive.
