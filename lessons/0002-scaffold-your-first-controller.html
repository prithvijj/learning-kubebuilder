Lesson 2 · Kubebuilder & Controller Internals

From Diagram to Running Code

Lesson 1 was the diagram: API server, Cache, WorkQueue, Reconcile(). Today you build the real thing — a Kind called Greeting, a controller that reacts to it, running against your own k3d cluster — and watch that diagram happen in your terminal.

Today's win: apply a Greeting custom resource with kubectl, watch your own Reconcile function log its name, and see it create a ConfigMap as a side effect. Then change the Greeting and watch it happen again.

Step 0 — a cluster to point at

You've already got mycluster running. That's fine to reuse, but a dedicated cluster keeps these lessons from colliding with anything else you're testing: 

k3d cluster create kubebuilder-lessons
kubectl config current-context   # should print k3d-kubebuilder-lessons

k3d cluster create merges the new cluster's kubeconfig and switches your current context to it automatically — that's why the check above matters before you run anything that mutates a cluster.

Step 1 — install the kubebuilder CLI

It isn't on your machine yet. Straight from the official docs:

curl -L -o kubebuilder "https://go.kubebuilder.io/dl/latest/$(go env GOOS)/$(go env GOARCH)"
chmod +x kubebuilder && sudo mv kubebuilder /usr/local/bin/
kubebuilder version

Step 2 — scaffold the project

mkdir greeting-operator && cd greeting-operator
kubebuilder init --domain kubebuilder-lessons.dev --repo greeting-operator

This writes main.go, a Makefile, and go.mod. Open main.go and you'll recognize it: it builds a Manager and calls mgr.Start(ctx) — that's the process that runs everything from Lesson 1's diagram.

Step 3 — define your own Kind

kubebuilder create api --group apps --version v1 --kind Greeting --resource --controller

This scaffolds two files that matter to you right now:

  • api/v1/greeting_types.go — the Go struct that is your CRD's schema.
  • internal/controller/greeting_controller.go — an empty Reconcile skeleton, wired to watch Greeting objects.

Step 4 — give Greeting a field

In api/v1/greeting_types.go, find GreetingSpec and add:

type GreetingSpec struct {
	// Message is written into a ConfigMap by the controller.
	Message string `json:"message"`
}

Then regenerate the CRD YAML and the DeepCopy methods your type needs:

make manifests generate

Step 5 — write Reconcile

Replace the body of Reconcile in internal/controller/greeting_controller.go. Map every line back to Lesson 1's vocabulary as you read it. First, make sure these imports are present — a couple (apierrors, controllerutil) are new packages the scaffold didn't already pull in: 

import (
	"context"

	appsv1 "greeting-operator/api/v1"
	corev1 "k8s.io/api/core/v1"
	apierrors "k8s.io/apimachinery/pkg/api/errors"
	metav1 "k8s.io/apimachinery/pkg/apis/meta/v1"
	ctrl "sigs.k8s.io/controller-runtime"
	"sigs.k8s.io/controller-runtime/pkg/controller/controllerutil"
	logf "sigs.k8s.io/controller-runtime/pkg/log"
)

apierrors.IsNotFound lives in k8s.io/apimachinery/pkg/api/errors — it's not exported from anything controller-runtime gives you directly, which is why it's easy to reach for the name before the import exists. If your editor runs goimports on save, it'll add these for you once the symbols are used. 

func (r *GreetingReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
	log := logf.FromContext(ctx)

	var greeting appsv1.Greeting
	if err := r.Get(ctx, req.NamespacedName, &greeting); err != nil {
		if apierrors.IsNotFound(err) {
			return ctrl.Result{}, nil // object gone — nothing to do
		}
		return ctrl.Result{}, err
	}

	cm := &corev1.ConfigMap{
		ObjectMeta: metav1.ObjectMeta{Name: req.Name, Namespace: req.Namespace},
	}
	op, err := controllerutil.CreateOrUpdate(ctx, r.Client, cm, func() error {
		if cm.Data == nil {
			cm.Data = map[string]string{}
		}
		cm.Data["message"] = greeting.Spec.Message
		return controllerutil.SetControllerReference(&greeting, cm, r.Scheme)
	})
	if err != nil {
		return ctrl.Result{}, err
	}

	log.Info("reconciled greeting", "configmap-op", op)
	return ctrl.Result{}, nil
}

Notice what's not here: nothing reads the incoming event. req is only a NamespacedName — the key from the workqueue. Every value you use (greeting.Spec.Message) comes from r.Get, which reads the Cache. This is Lesson 1's "level-triggered" point, made concrete.

Add this marker above the Reconcile method so make manifests grants your controller permission to touch ConfigMaps:

// +kubebuilder:rbac:groups="",resources=configmaps,verbs=get;list;watch;create;update;patch

Then regenerate once more: make manifests.

Step 6 — install the CRD, run the controller

make install   # teaches your k3d cluster's API server the Greeting schema
make run       # runs the manager locally, against your k3d cluster — leave this running

Leave make run in its own terminal — its log output is where you'll watch Reconcile fire.

Step 7 — apply your own custom resource

Open config/samples/apps_v1_greeting.yaml, add a message, and apply it from a second terminal:

spec:
  message: "hello from my own CRD"
kubectl apply -f config/samples/apps_v1_greeting.yaml
kubectl get configmap greeting-sample -o yaml

You should see a log line in the make run terminal, and a ConfigMap holding the message you wrote. That log line, that ConfigMap — that's the right-hand side of Lesson 1's diagram, no longer a diagram.

Now the important experiment: edit the sample file's message to something else and kubectl apply again. Watch Reconcile fire a second time in the logs, and kubectl get configmap greeting-sample -o yaml again to confirm it updated. Nothing in your code branches on "this is an update, not a create" — CreateOrUpdate and your own re-read handle both identically. That's what level-triggered buys you.
