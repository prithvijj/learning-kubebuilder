Testing Reconcile with envtest

Every check so far has been you, a terminal, and k3d. That doesn't scale to CI, and it's slow for quick iteration. Kubebuilder already scaffolded a test suite for exactly this — you just haven't run it yet.

What envtest actually is: a real etcd and a real kube-apiserver, run as local binaries for the duration of the test. Full CRD validation, full watches — your Reconcile function can't tell the difference from a real cluster. What's missing on purpose: no kubelet, no scheduler, and no built-in controllers — which means no garbage collection. It's a deliberately smaller layer than k3d, not a replacement for it.

Step 0 — look at what's already there

Two files already exist in internal/controller/:

  • suite_test.go — boots envtest.Environment in BeforeSuite, pointed at your CRDs in config/crd/bases, and builds a real k8sClient against it. Tears it down in AfterSuite.
  • greeting_controller_test.go — one Ginkgo test, "should successfully reconcile the resource."

Run it as-is:

make test

First run downloads matching etcd/kube-apiserver binaries via setup-envtest into bin/k8s/ — that needs network access once, then it's cached.

It should fail. Look for a validation error mentioning spec.message. Before you fix it — go check why: 

grep -A3 "required:" config/crd/bases/apps.kubebuilder-lessons.dev_greetings.yaml

Because Message in GreetingSpec has no omitempty and no +optional marker, controller-gen put it in the CRD's required list. The scaffolded test's BeforeEach creates a Greeting with an empty Spec{} — no message — so k8sClient.Create is rejected by real API validation, same as it would be against k3d.

Step 1 — fix the test's setup

In greeting_controller_test.go, inside BeforeEach:

resource := &appsv1.Greeting{
	ObjectMeta: metav1.ObjectMeta{
		Name:      resourceName,
		Namespace: resourceNamespace,
	},
	Spec: appsv1.GreetingSpec{
		Message: "hello from envtest",
	},
}

Run make test again — it should pass now. But look at what it's actually asserting:

_, err := controllerReconciler.Reconcile(ctx, reconcile.Request{
	NamespacedName: typeNamespacedName,
})
Expect(err).NotTo(HaveOccurred())

That only proves Reconcile didn't return an error. It doesn't prove the ConfigMap exists, or that its data is right, or that the Ready condition got set. A test that only checks "no error" would pass even if you deleted the entire body of Reconcile.

Step 2 — assert what you actually built

Add these imports to greeting_controller_test.go:

corev1 "k8s.io/api/core/v1"
"k8s.io/apimachinery/pkg/api/meta"

Then, right after the existing Expect(err).NotTo(HaveOccurred()):

By("checking the derived ConfigMap")
cm := &corev1.ConfigMap{}
Expect(k8sClient.Get(ctx, typeNamespacedName, cm)).To(Succeed())
Expect(cm.Data).To(HaveKeyWithValue("message", "hello from envtest"))

By("checking the Ready condition")
updated := &appsv1.Greeting{}
Expect(k8sClient.Get(ctx, typeNamespacedName, updated)).To(Succeed())
Expect(meta.IsStatusConditionTrue(updated.Status.Conditions, "Ready")).To(BeTrue())

make test once more — now a passing test actually means something: ConfigMap data matches spec, and the condition your Lesson 4 code sets is really there.

Step 3 — the boundary envtest won't let you test

Try adding a test that deletes the Greeting and expects the ConfigMap to disappear, the way you watched it happen for real in Lesson 3: 

Expect(k8sClient.Delete(ctx, updated)).To(Succeed())
Eventually(func() bool {
	return errors.IsNotFound(k8sClient.Get(ctx, typeNamespacedName, &corev1.ConfigMap{}))
}).Should(BeTrue())

This will hang and time out. Not a bug in your code — envtest never runs the garbage collector, so no owner-reference cleanup ever happens here. That specific behavior can only be verified against a real cluster like k3d. Delete this experimental block once you've seen it fail; it's not something envtest can ever pass.

Primary source Kubebuilder Book — envtest reference for the exact list of what does and doesn't run. For Ginkgo/Gomega syntax itself (Describe, By, Eventually), see the Ginkgo docs.
